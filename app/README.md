# 3 · App: racecars

The site: **racecars** (racecars.fun) - Vite + TypeScript + three.js. The landing (`/`) is the game's hub; the game is the drive page (`/drive.html`) and online races (`/online.html`, a separate game server); the pack-rip reveal of stage 2's cars, the RIPCARS prototype this app started as, is now a dev-mode page (`/rip.html`).

```sh
cd app
npm install
npm run dev -- --port 5199     # http://localhost:5199/ (the landing); the reveal: /rip.html?car=skyline-hck01
npm run server                 # the game server (online races, the leaderboard, garages): see Multiplayer
npm run build                  # static site in dist/ (vite preview serves it)
```

A top bar on every page: **RACECARS** (home: the landing), **Drive**, **Race online** (`/online.html`, multiplayer: see *Multiplayer* below) and **Rip a pack** (https://ripcars.io, where the Rip Cars come from, in a new tab), and in dev mode the tools - **Reveal** (`/rip.html`) and **Inspect** (`/inspect.html`) - with a DEV badge by the logo. On the reveal and the drive page a car picker and *Random*; following a link keeps the car you are on. At its right end the wallet chip: *Connect wallet* signed out; signed in, your wallet's icon and short address, with *Copy address*, *Dev mode* and *Disconnect* (your wallet is your name in online races: *Wallet sign-in* below). The bar never wraps: as it narrows the car picker shrinks, then *Random* and the wallet chip go to icons, the links go short, then the phone layout (on a phone with the car picker, *Rip a pack* steps out; in dev mode the tools step out under 640 px - they open by URL, and the landing's foot links them). The bar hides itself in the `mode=` screenshot views and inside the inspector's embedded reveal.

**Dev mode** (`src/dev.ts`): a switch in the wallet chip's menu (signed in) and in the wallet picker's footer (signed out), or `?dev=1` / `?dev=0` on any URL; kept in `localStorage` (`ripcars.dev`; every tab follows). It adds the tools to the top bar and the landing's foot, and lets the landing show any wallet's garage (`?garage=<wallet>`). Off, the tool pages still open by URL (scripts need them).

**Old links**: `/` with the reveal's knobs (`car=`, `mode=`, `t=`, `card=`, `az=`, `el=`, `yaw=`, `unlit=`, `reveal=`, `rarity=`) redirects to `/rip.html` with the same query (index.html's first script), so `/?car=<id>` links still open the reveal.

The app serves `asset-generation/assets/` directly (`vite.config.ts` → `publicDir`), so `/cars/<id>/…` is whatever stage 2 last built. `npm run build` copies that whole folder into `dist/`, then `scripts/prune-dist.mjs` drops what the site never loads (Tripo's downloads, snapshots, masks).

## The landing

`index.html` + `src/home/` (`main.ts`, `style.css`, `turntable.ts`, `tracks.ts`, `img/`): the hub, top to bottom -

- **Your car**, big: the signed-in wallet's best drivable Rip Car (rarest, then most valuable), else the featured one (the LB-ER34 Skyline), with **Race online** and **Drive** (both with that car) and a live line when rooms are open (*2 rooms open · 5 players*). First paint is a still of the car (`img/car-<id>-1440/640.webp`); the 3D turntable (`turntable.ts`: the drive page's own car, `drive/rig.ts`, turning on a dark stage - drag to spin it) replaces it once the visitor touches, scrolls or types, or, on a computer (a fine pointer, 8+ cores), once the page has loaded and gone idle. It renders only while on screen. No three.js before that: the landing's first load is ~18 kB of JS and CSS gzipped (the reveal that used to be `/` loaded 206 kB).
- **This week**: a card per track - its still (`img/track-<id>-1600/800.webp`, frames of the game itself), **Time trial** (a room of your own on that track: below), **Race** (`/online.html?track=<id>`, that track's rooms) and **Drive** (solo, offline) - and its board: the top 10 wallets by their best lap this week without car-to-car contact (rank, short wallet, car, time), yours highlighted, and your rank under the top 10 when you're further down; *Resets in 2d 4h* (Monday 00:00 UTC).
- **Open rooms**, live (`GET /rooms` every 3 s): name, track, laps, who's in, *Join*; **Create room** (the lobby's own dialog: `src/create-room.ts`); *All rooms* → `/online.html`.
- **Garage**: signed in, the wallet's Rip Cars from RIPCARS (`GET /garage`) - photo, name, rarity; the ones the game has a model of first, with a *Drivable* badge and *Drive*; the rest muted. No Rip Cars: one line and *Rip a pack*. Signed out: *Connect wallet* and the cars you can drive (renders of the models).
- Each part stands alone: no game server → *Game server offline* / *Leaderboard offline* (and Time trial / Race / Create disabled); RIPCARS not answering → *Can't reach RIPCARS right now*; everything else still works.

Knobs: `?server=ws://host:port` (another game server), `?garage=<wallet>` (dev mode). `window.__home` has its data for scripts.

**Its pictures** come from the game: `node scripts/render-home.mjs [cars] [tracks] [only=<id>]` (the dev server running) renders every modelled car on the turntable at its first frame (`stills.html`, a dev-server page that isn't built) and each track's still - the autopilot drives a lap and the frame is held at the course's moment (the meadow's big jump in its side-on shot at 43.2 s, the Sky Tower's sky jump by its hoop at 57.3 s; `MEADOW_AT` / `SKY_AT` to try others). Rerun it when a car's model or a track changes; a car without a render falls back (no picture).

## Two kinds of car

- **Modelled** (`model.glb` + `alignment.json` from stage 2): the full 360° reveal. `src/model.ts` loads the GLB, swaps in the reveal material and glues the pack photo onto the model through the landing pose. That projected photo is what makes the hand-off seamless. The GLB can come from the `ripcars` scripts or be a promoted Tripo mesh; either way its wheels are `wheel_*` pivot nodes, which the reveal spins whole turns, so they land back at rest on the photo. Windows are the texels marked as glass in its roughness map; `src/glass.ts` makes them see-through.
- **Procedural fallback** (no `model.glb`, needs `params.json`): `src/car.ts` builds a car from the pack-photo outline alone. It reveals near side-on and morphs from a generic coupe into the car. Force it with `?reveal=profile`.

## Drive page

`/drive.html?car=<id>` takes the car for a spin on one of two courses, picked with `?track=` or the *Meadow | Sky Tower* switch in the top bar (under 1200 px wide it hangs below the bar's right end):

- **Meadow** (the default; `?track=meadow` or no `track`): a 2,740 u lap for a 4 u car, about 65 s. Twisty asphalt roads with mown grass verges, tyre walls and hay bales, a loose dirt stretch, and orange Hot Wheels plastic for the set pieces only - the raised start gate and its drop, a small kicker over a gap on scaffolding, the big jump (a booster up a steep ramp on a tall scaffold tower, about 2.3 s of air over the road below, a long landing ramp; a pond and a RIPCARS banner beside it), a booster into the loop and a banked climb on stone pillars back to the gate.
- **Sky Tower** (`?track=sky`): track 2, the crazy one - the Hot Wheels Sky Crash Tower set with a Trackmania edge. The gate sits high on a tall blue lattice tower; the plunge drops off it in the narrow classic channel straight into a loop, then come chained boosters, a steeply banked 180, a double jump and the wall ride - a 180 banked at 70° that you drive up onto from the meadow, with one narrow booster pad in the middle of its approach (line up for it, or ride the wall slower) - then a single rounded crest in the straight off the wall ride (1.6 u high, 32 u long), esses and a chicane where drifting pays, a rhythm section of two long rollers on the wide straight east to the climb (2 u high, 46 u crest to crest; `SKY_BUMPS` in `tracks/sky.ts`), the climb (a row of chained pads into a ramp that goes up past vertical, over the top upside down and rolls out into a banked right-hander onto a deck 41 u up - Hot Wheels' up the wall and over: it's the pads' speed that carries you, and a car that comes to it too slow falls off and is put back before the pads; the right-hander tightens to an 18 u radius as it narrows to 11 u, a drift corner), the sky bridge (the narrow deck flares and splits into two lanes, 9.5 u each, either side of an island - a gap you see the meadow through, its striped points walls like any rail - and each lane has its own jump: the left one early and steeper, ~1.6-1.7 s of air, the right one later and flatter, ~1.5-1.6 s; both lanes widen outward into catch trays over the landings and lap within a few hundredths of each other; you take the lane on the side you're on at the island's point, and a miss puts you back in that lane, lined up, before its jump; `BRIDGE` in `tracks/sky.ts`, the split itself in `tracks/split.ts`), the sky jump's in-run (the deck runs on north, and off its far end the dive turns right and down: a 270° descending right-hander, banked 20°, that comes back round and passes UNDER the deck - the classic Hot Wheels over/under, ~16 u of headroom, the deck's stilts standing clear of it - lines up, then plunges at 11° where the speed builds, to a booster pad at its foot) and the sky jump itself (a short steep kicker low down, up and over a gap through a hoop onto a long ski-slope landing hill: the biggest air in the game, ~3.3 s; land early near its top or further down - anything from 0.85 to 1.15 of the run-up's speed lands lined up; manual like the meadow's big jump, so a straight hit lands perfect), and the spiral climbing round the tower back up to the start. It is built for racing side by side: most of the lap is wide enough for three or four cars abreast (the meadow's plastic channel takes two), narrowing to the classic channel only where the squeeze is the point (the plunge and its loop) and to the small toy tracks of the sky bridge, with a start grid for 8 cars at the gate.

A course is one file in `src/drive/tracks/` exporting a `Course` (`tracks/course.ts`): its id, name, blurb and colour, its layout (written with the `Path` pieces in `tracks/path.ts`, two free straights closing the lap), the start line, its own support kinds and set dressing, the world style, and its medal pace (`pars`, measured with the autopilot). Adding track 3 is that file plus one entry in `COURSES` (`tracks/index.ts`); the track switch, *Try*, the bests' keys and the medals pick it up from there.

Three laps, splits against your best lap, results with a medal, *Again*, *Rip a pack* (ripcars.io, a new tab) and *Try* the other course. Bests (and the air record) are kept per car and course in `localStorage`: `ripcars.drive.<car>.<lap length>` on the meadow (the key it had before track 2, so earlier bests stand) and `ripcars.drive.<car>.sky.<lap length>` on the Sky Tower; a layout with a new length starts afresh. Changing course reloads the page with the same car and URL knobs (`auto`, `laps`, ...); the bar's car picker and *Random car* keep the course. The reveal's *Take it for a spin* button and the top bar's *Drive* link from the other pages open the meadow for the car you are on. The car waits in the start gate under the course's name; the first key, tap or pad button drops it and unlocks the sound.

- **Keys**: W / ↑ gas, S / ↓ brake and reverse, A D / ← → steer, Space or Shift drift, R restart, M mute. **Pad**: stick, RT / LT, A or RB drift, Start restart.
- **Touch**: the car drives itself; drag anywhere to steer. Hold full lock (or tap a second finger) to drift; centre the thumb or lift it and the car straightens, which ends the drift and fires the boost.
- A drift is a tap, not a hold: the rear goes loose and the slide is yours - steer to hold it, counter-steer or lift to catch it. It ends by itself once the car is straight again (or at a second tap). Slide long enough and the sparks go blue, purple, then the car's tier colour (0.9, 1.8 and 2.7 s of real sliding), and a slide kept going twice as long as gold, linked through a whole S, hits a hidden fourth: the *magic max*, with its own sparks, chime and a longer, stronger boost. A drift that ends clean fires a boost that grows with the tier (a wall hit or a spin cancels it). Land a jump straight for a PERFECT boost. Booster pads, two jumps and a loop are on the meadow's lap. The big jump flies off whatever you bring to the lip - hit the booster fast and straight, leave the wheel alone in the air for a PERFECT; miss and you're put back before the run-up.
- **Boosts stack.** Every boost - a booster pad (1 s of push, plus its instant +8 u/s kick), a drift's mini-turbo (0.5 / 1 / 1.5 s by tier, the magic max's 2.5 s and 1.3x stronger) and a PERFECT landing (0.5 s) - pours its time into one shared tank, so nothing is wasted: a big drift cashed in just before a pad runs on after the pad's push. The tank burns its strongest push first (pad and landing, then the magic max's, then a mini-turbo's), so a lone boost pushes exactly as it always did. Each boost added while the tank is still running is a stack (`state.boostStack`; no text pops up: the flames, sound and speed show it): it raises the boost's top speed by 4 u/s (56 alone, 60 at x2, 64 at x3 ...), fading back over the tank's last second; the stack is gone once the tank is empty. There is no cap on the tank or the stacks - a run of pads throws the car as fast and as far as the physics says, and stacking into a jump can carry it past the landing (then the usual miss rules put it back). The flames burn longer, wider and hotter and the boost hiss and engine get louder per stack. The Sky Tower's chained pads stack to x3 on every lap (the meadow's pads are too far apart).
- **Air records**: the longest landed flight (0.9 s or more) is kept per car and course with the bests (the same `localStorage` key, as `air`); beating one from an earlier race says so as the car lands (*Big air 4.6 s, record!*), and the results card shows the race's longest air against the record.
- Each car drives and sounds like itself (`PROFILES` in `vehicles/arcade.ts`, multipliers on the shared tuning; `ENGINES` in `audio.ts`), and medals are judged against each car's own pace on each course (each course's `pars` in its `tracks/<course>.ts`: the autopilot's average speed over 3 laps; a course without a car's number uses its meadow pace, so the par time scales with the lap's length):
  - **Porsche 911 GT3 R** (Roxy): the most grip, the hardest brakes, the sharpest steering and the highest top speed, but hard to get sideways and slow on dirt. A flat-6 race wail with crackles on the lift.
  - **Skyline LB-ER34**: a breath of turbo lag, then the strongest mid-range pull; the easiest, most controllable drifter. An RB26 inline-6 with turbo whistle and a blow-off on every lift.
  - **1964 Impala**: a heavy, soft boat with a lower top speed, lazy steering and big floaty slides, but at home on the dirt and the one that carries a hill's speed furthest. A big-block V8 burble through a lazy 3-speed automatic.
  - **Porsche 911 GT3 RS**: the road-going racer, a step below the GT3 R on grip, with a flat-6 that revs to 8,400 through a 6-speed manual.
  - **Porsche 964**: an air-cooled classic 911 whose tail swings readily on a lift. A dry, raspy flat-6 and a 5-speed.
  - **'77 Firebird Trans Am**: a muscle car that pulls hard out of corners, fades up top and steps its tail out under power. An angry V8 through a 4-speed.
  - **Beach Bomb Too**: the VW bus with surfboards, the slowest car, tall, soft and floaty, but happy on the dirt. An air-cooled flat-4 putter.
  - **'99 Civic Type R**: a light front-drive hot hatch, nimble and grippy but hard to get sideways. A VTEC four screaming to 8,400.
  - **'93 Mustang Cobra R**: a Fox-body V8 with a strong low-down shove and a willing tail. A 5.8 V8 through a 5-speed.
  - **'65 Nissan Silvia (CSP311)**: a small, light coupe - modest pull and top speed, but the quickest to turn in and easy to place; light, so knocks throw it about. A nasal 1.6 four on twin carbs, revving to 6,600 through a 4-speed.
  - **'73 Volvo 142 GL**: a heavy, boxy sedan - slow to get going and lazy to turn, but a tank in a crash, it carries a hill's speed and likes the dirt. The B20 four's low thrum and a long-throw 4-speed.
  - **1964 Jaguar E-Type**: a long, low GT - a high top speed it holds on to, a long smooth slide, a lazy long nose and period brakes. The XK straight-six's howl through a 4-speed.
  - **Splittin' Image**: a light Hot Wheels fantasy racer - explosive pull, a loose and lively tail, quick steering; no dirt car. A blown big V8 with the lumpiest idle in the game and pops on every lift.
  - **Godzilla, green and gold Skylines and the white-and-yellow LB-ER34 (JBK59)** drive and sound like the other Skyline (same RB26). A car without its own entry drives the stock car and gets an engine by make.
- Drive against the lap and a WRONG WAY sign comes up; after 4 s of it, or 4 s stuck, the car is put back on the track facing the right way. A missed jump puts it back well before the booster.

The driving model is hand-written (`src/drive/vehicles/arcade.ts`, no physics engine): the car lives in track space, gravity is projected onto the track so slopes, banks and the loop just work, and it flies off any crest it's too fast to stay on (see *Crests and bumps* above). Each surface grips and tops out differently (plastic fastest, asphalt grippiest, dirt loose and bumpy, the grass verge slow and slippery). The throttle pushes only up to the car's top speed; past it only the air drags, gently, so a hill (the start drop, the big jump's landing ramp) carries the car well over its top speed into the next corners, where the tyres grip no harder than at top speed: brake, or take a wider line. Walls push back at the corner that touches, with the restitution and friction of what they are made of (plastic rail, tyre wall, hay bales): a glancing hit scrapes along, a hard one stuns for a moment, a very hard one spins the car out (hay bales only swallow the hit and slow the car, never spin it), and the car never sticks to a wall. The simulation runs in fixed 1/120 s steps and is deterministic and input-driven - no randomness, no clocks, and game time never slows or stops (no slow motion, no hit-stop), so it can run in lockstep for multiplayer later; a hard hit's drama is the camera's kick, shake and FOV punch, the sound, the sparks and the haptics. Everything is generated in code, sounds included; the only downloads are the car's GLB and JSON.

**Crests and bumps throw the car**: it leaves the track wherever the track can't hold it at its speed - the same test as the loop's (gravity into the surface against the speed's pull off a crest), with only a little toy-track magnet (`hopStick`, 0.15 g) - flies the same ballistics and lands with the same landings. So the Sky Tower's bumps throw it: at race speed it hops from crest to crest through the rhythm section (two long rollers, ~0.5 s of air each at race speed) and flies ~0.7 s off the crest after the wall ride; slower, it rolls over them. A hop is quiet: it shows as airborne (dust, sound, camera) once it's 0.1 s or 0.25 u clear of the track, it isn't steered (the wheel held through it doesn't twist the car: it lands straight), and only a flight of 0.9 s or more is graded (PERFECT, ok, bad). Banked turns (over 15°) hold the car, there's no new hop within 0.1 s of a landing (no buzz), and the set pieces fly, fall or hold as built: both big jumps (in-run, lip, gap, landing ramp), the kickers, the loops, the climb, and the start drops (the Sky Tower's plunge would throw a car 1.3-1.7 s down the tower into the loop's mouth, so it holds). The meadow has no crest sharp enough to throw a car at its speeds. It's all deterministic.

## Multiplayer

Race other players against a small server that runs the game's own simulation. You race as your Solana wallet: connect it and its address is your name (*Wallet sign-in* below). Locally it's a demo for tabs on one machine; the plan is the site on racecars.fun (Vercel) and this server hosted on its own (play.racecars.fun, say: see the env vars below).

```sh
cd app
npm run dev -- --port 5199     # the page, as usual
npm run server                 # the drive server: ws://localhost:8790 (stats: http://localhost:8790/stats)
```

**Playing from the UI** (no URL to type):

1. **Race online** in the top bar (or the landing's *Race online*, a track card's *Race*, or *Race it online* at the end of a reveal) opens `/online.html`, the room browser: who you race as (signed in: *Racing as* your wallet's short address; signed out: *Connect wallet*) and your car (remembered), then the open rooms - all of them or one track's (the switch; `?track=<id>`) - name, track, laps, players x/10 with their short wallets and cars (★ the host), and whether it's waiting, starting or racing - refreshed every 2 s, each with **Join** (a racing room: you're in its next race; a full one says *Full*). No rooms: *No open rooms*; no server: *Game server offline* (in dev mode with the command that starts it). **Join** and **Create** need a signed-in wallet: signed out, they open the wallet picker first, then go on to the room.
2. **Create room** (`src/create-room.ts`, the landing has the same): a name (filled in - your wallet's first four characters and a number - editable; a name that's already open is refused, with a link to join it), the track (Meadow / Sky Tower, as their stills), laps (1, 2, 3, 5) and *Fill with bots* (off, 2, 4, 6 server-driven cars that race like decent players: *Bots* below). It opens the room.
3. **In the room** (the drive page, the car on its grid slot behind the card): the course and laps, the room's name, **Copy invite link** (a link that drops a friend straight into this room with their own wallet and car; opened signed out, the card asks them to connect a wallet first, then they're in), the players - each by their short wallet - with their car, Ready state and ping (*You*, *Host*: the room's first player, then the next in join order), who you race as (your wallet) and your car - changed in place, everyone's list follows (a car change un-readies you; between races it takes effect back in the lobby; the top bar's car picker does the same) - a big **Ready** (or Enter), a line saying what it's waiting for, and *Leave room* (back to the browser). When everyone is ready: 3-2-1 and the gate drops for all at the same step.
4. **Race**: the top right shows your position, the standings (short wallets) and your ping; the other cars carry name tags (their short wallets) - and you can crash into them (*Crashing into each other* below). Join mid-race and the card says you're in the next one.
5. **Results**: the finish order with the winner's time and everyone's gap (DNF 30 s after the winner), **Race again** (back to this room's lobby) or **Leave**. The results stay up until you choose; the room goes back to its lobby 8 s after the race, or as soon as every player has pressed Ready again.

`drive.html` without `online=1` is the single-player page exactly as before (nothing of the online code loads, no wallet needed). The URL still works by hand (handy for tests): `http://localhost:5199/drive.html?online=1&room=demo&car=skyline-hck01&track=sky` - signed in it joins, signed out it asks you to connect first; a second player is another wallet in another browser profile (the same wallet in a second tab takes your car there: *one wallet, one car*). The invite link is this URL without the car. `GET http://localhost:8790/rooms` is the browser's list as JSON.

**Wallet sign-in** (`src/auth/`, `server/auth.ts`): a player is a Solana wallet - its address is the username, proven to and checked by the server - so later the cars you race (and win) can be other players' car NFTs.

- **Connecting**: the top bar's *Connect wallet* (or the lobby's, its Join / Create, or an invite link opened signed out) opens the wallet picker - every wallet in the browser that speaks the Wallet Standard on Solana mainnet with `standard:connect` and `solana:signIn` or `solana:signMessage` (Phantom, Solflare, Backpack, Jupiter, OKX ...; one that registers while the picker is open shows up), each with its icon. Pick one, approve the sign-in in it ("Free, no transaction"), done. No wallet: on a computer, install links (Phantom, Solflare, Backpack; reload once installed); on a phone, *Open in Phantom / Solflare / Backpack* - this page in the wallet app's own browser (`https://phantom.app/ul/browse/<this url>?ref=<this origin>`, `https://solflare.com/ul/v1/browse/...`, `https://backpack.app/ul/v1/browse/...`), where the wallet is. No React, no wallet-adapter: `@wallet-standard/app` finds the wallets, `@solana/wallet-standard-util` writes the Sign In With Solana message (exact versions pinned); the picker and the wallet code load only when someone connects (a 5 kB gzipped chunk), the top bar's chip costs ~3 kB gzipped per page, and no crypto library ships to the page (the server verifies).
- **Sign In With Solana, verified by the game server**: `POST /auth/challenge` -> the server makes the whole sign-in request - domain and URI from the page's origin (only an allowed origin), the statement *Sign in to race on racecars. Free, no transaction: it only proves this wallet is yours.*, version 1, chain mainnet, a random single-use nonce, issued now, expiring in 10 min - and remembers it by its nonce (in memory: expiring, at most 10,000, 30 a minute per IP). The wallet signs it - `solana:signIn`, or `standard:connect` + `solana:signMessage` of the same text (`createSignInMessageText`) - and `POST /auth/verify` sends the nonce and the wallet's output (address, public key, signed message, signature; bytes as base64). The server takes the request from its own record (never the client's), burns the nonce on the first try (good or bad), checks the address is the public key's (base58), the signed message is exactly the request and the signature is that key's (`verifySignIn`), and returns a session token: HMAC-SHA256 over {wallet, iat, exp} with `AUTH_SECRET`, good for 24 h, checked without any state. Another proof of a wallet (a Privy login, say) would end in the same `issueSession()`.
- **The session** (`src/auth/session.ts`): the token, the wallet, its expiry and the wallet's name and icon in `localStorage` (`ripcars.session`, shared by every tab). Racing needs only the token, so a reload doesn't sign again. *Disconnect* clears it (and asks the wallet to forget the site; in a room, the page starts over and asks you to connect). A token the server turns down - expired, or the server restarted with a new secret - is dropped and asked for again: the lobby checks it on load (`GET /auth/session` -> `{ wallet, exp }`, or `{ wallet: null }`), the room says *Sign in again* and joins once you have.
- **The server**: `join` carries the token; a join without a valid one is refused (`error`, `code: 'auth'`; the page signs in again and joins on the same connection). The player's name is the wallet's short form (`7xKX…9fQ2`, `shortWallet` in `src/auth/address.ts`), set by the server: nobody picks or changes a name (there's no rename any more). Results, standings, name tags, the room list and the lobby show it; `PlayerInfo` and `GET /rooms` carry the full `wallet` too. Bots are the server's and need no wallet. Race logs carry each car's wallet in the header (`wallet`, null for a bot; the log version, the sim and `replay.ts` are unchanged). `mayDrive(wallet, car)` in `room.ts` is where the ownership check of the chosen car goes (the join and every car change ask it; for now any car).
- **One wallet, one car**: one connection per wallet on the whole server. A join from a wallet that's already connected - another tab, another device - closes the older connection: its car leaves (as on a disconnect: mid-race it drops out) before the new one joins, and that page says *Racing elsewhere - You joined from another tab or device* (with *Race here*). A wallet never has two cars, not even for a moment of five joins at once; a join refused because the room is full leaves the car where it is.
- **Origins**: CORS on `/auth` only for the allowed origins (anything else gets a 403 without CORS headers); a browser's WebSocket from any other origin is refused (403). A client that isn't a browser sends no Origin: allowed, but it still needs a valid token to join.

**With a real wallet, locally**: http://localhost:5199 works - a browser treats localhost as a secure origin, and it's on the default list. Install Phantom (or Solflare, Backpack) in the browser, run `npm run dev -- --port 5199` and `npm run server`, open http://localhost:5199/online.html, *Connect wallet*, pick it: the wallet shows the request (localhost:5199, the statement, the nonce; no transaction, no fee) - approve, and you're *Racing as* your address. **Time trials** (the landing's *Time trial* on a track): a room of your own - `drive.html?online=1&solo=1&room=tt-<track>-<random>&track=<id>&laps=3` - raced on the game server like any room, but solo: no bots, nobody else may join (*That's someone's time trial*), and it isn't in the room list. Its card: *Time trial*, your place on this week's board (*This week #4 · 1:02.375*), your car, **Start**; after each run its laps (the best lit), the total and your place again (*New best* when it is), **Again** (straight into the next run) or **Leave** (home). Its laps count for the board like any clean race lap.

**The leaderboard** (`server/store.ts`, `GET /leaderboard`): every lap a signed-in player completes in an online race is stored - wallet, car, track and its lap length, the lap time in sim steps exactly as the race counts it, the lap's number, the room, its race number, the race's log, the server's time, how many cars raced, and two contact flags from the contact solver (`net/contact.ts` `touchedLast`, kept per car by `server/sim.ts`): **`contact`** - the car's box met another car's at all during the lap - and **`pre`** - it did in the 3 s before the lap began (a push over the line carries its speed into the lap). Bots' laps never are (they have no wallet). The page's autopilot (`?auto=1`, which the join now says) is stored with `auto = 1`. **Only clean laps count**: no contact either way, not the autopilot's - so a push from another car or a bot can never make a record (time trials are solo anyway). The race log's lap lines carry the same flags (`c`, `pc`) and `replay.ts` checks them against the re-simulation (*laps: 6 with contact flags (5 touched another car), MATCH*). The board is the ISO week's - Monday 00:00 UTC to the next - per track and per lap length (a re-laid track starts a new board): each wallet's best clean lap (the earlier one on a tie), the top 10, and the asking wallet's own best and rank.

**Garages** (`server/garage.ts`, `GET /garage?wallet=<address>`): the wallet's Rip Cars from RIPCARS's public API, fetched by the server (it has no toy numbers in its list and no CORS for other sites): `my-cars?wallet=` (cached 60 s per wallet; while RIPCARS doesn't answer, the last one for 10 min, marked `stale`), then each mint's toy number from `assets/<mint>` (`toyNumber`; once per mint, kept in the store for good, three lookups at a time; a request waits up to 6 s for them, then answers `partial` - the landing asks again). A toy number the game has (each car's `meta.json` `"toy"`: the reference manifest's `product_code`, the NFT's *Toy #* attribute - e.g. the 911 GT3 RS is HRX26) maps to that car: `model` is its id, drivable. Matching is by toy number only: a Porsche 964 of another release (DJF93) is not the game's 964 (GDF88). Drivable first, then the rarest, the most valuable, the newest. The cars are Metaplex Core assets of the *Rip Cars* collection (DiRqf7eyipQ7nPKtjWzFUZRyWT3M63GC75qyMDHe9Z81); racing doesn't check ownership yet (`mayDrive`). A malformed wallet → 400; 20 garages a minute per IP (each miss costs requests to RIPCARS) → 429; RIPCARS down with nothing kept → 502.

`/rooms`, `/leaderboard` and `/garage` are public GETs, open to any site (CORS `*`).

**Crashing into each other** is the game's own physics, the same on the server and in every page, tuned to feel like solid toy cars, not pinballs: two cars meet as real impacts between their boxes - each car's own footprint (the box that hits the walls) standing as tall as its model, its mass its profile's heft (the Impala 1.35 and the Beach Bomb 1.3 shove the Civic 0.85 and the Porsches 0.9 about), its yaw inertia 2.5 x a box's (the tyres resist being turned). The hit lands at the corner or edge that touches, with a dull knock rather than a bounce (restitution 0.1; the rails' is 0.3), friction along the flanks (0.25) and the turn that impulse makes about each car's middle, at most 1.5 rad/s a step (as a wall's kick is capped) - so a door-to-door nudge moves the other car a few tenths of a unit and it keeps control, a 20 u/s T-bone knocks it a couple of units sideways with a wobble, a heavy car rear-ending a light one pushes it on (bump drafting), a head-on stops both, two cars side by side trade paint and lean on each other, and only a big T-bone on the rear quarter or a real PIT at speed spins a car round. A push across a car's nose is a sideways slide its tyres scrub off at 36 u/s^2 (it smokes and squeals), never turned into speed along the nose; pushes build that slide up to 12 u/s at most (one hard hit knocks a car as hard as it is), and the slide keeps its way in the world while the car turns under it (a car spun by a hit slides on the way it was sent). A car pressed against a rail can't be pushed further into it: the rail takes that part of the push and the car pushing takes the whole bounce - being sandwiched never launches you off the rail or slams you into it. The walls' own rules judge a hit: its speed times the other car's share of the mass (the wall it was as good as) ends a drift, stuns and spins out at the walls' thresholds; a hit behind a car's middle, square on and as hard as a 14 u/s wall hit (28 u/s between two cars of the same heft), knocks the tail out and spins it; and pushes on the rear quarter that close faster than a touch build up yaw - past 3 rad/s at over 30 u/s, a PIT, it spins. Nudges, scrapes and resting contact (door to door, nose to tail) never spin anyone. It works on banks, round the loops, up the wall ride and in the air (cars knock each other off line mid-flight; one coming down on another's roof bounces off it), never through a split's island, and not with a car that was just put back on the track (it passes through for a second) or one that has finished. A crash plays like a wall hit: sparks at the contact point, a metal bang by severity (the heavy thud and the boom on a hard one) or a grinding scrape, the camera's kick, shake and lens punch toward the car that hit, rumble; the other cars' crashes show their sparks and a knock by distance.

**Bots** (*Fill with bots*, `bots=<n>`) are the game's autopilot driven on the server, every input through the same quantize and checks as a player's, racing in traffic (`input.ts` `createAutopilot({ traffic })`; `server/sim.ts` hands each bot the race as it stands at the start of the step - every car's place, speed and size): off the grid a bot keeps its lane and eases toward the line (no dive across the pack), and it picks its line across the road among slots a quarter of a unit apart - near the line and where it's steering already, 0.8 u clear of the cars beside it (never across one), clear of the ones it's catching where they'll be - inside the narrowest the road gets over the next ~0.9 s, so a funnel ahead (the Sky Tower's plunge) squeezes it in early. Boxed in with no slot clear, it gives way to the car that has the place - ahead, or level and nearer the line - by lifting, and braking while the road closes in, and tucks in behind (the pack zips into the plunge two abreast: the inner slots first); a car ahead in its path that it's catching, it follows at a gap (1 u + 0.1 s), easing off the throttle smoothly rather than running into it, unless it's going round it; no drift with a car close by. It bumps now and then, it never rams. Alone it laps exactly as the plain autopilot (within 0.01% over 3 laps, every car, both courses); deterministic (a function of the race's state); single player and `?auto=1` don't use any of it (bit-identical).

**How it works** (`src/drive/net/`, `server/`):

- **Authority**: the server (TypeScript on Node, `server/index.ts`) runs the same code as the page - `vehicles/arcade.ts` on the `tracks/` course, then car-to-car contact (`net/contact.ts`) - for every car at 120 Hz. Clients send only their inputs; nothing a client says about its position is trusted. The hot messages are binary (`net/codec.ts`: 60 Hz snapshots down, inputs up); the rest is JSON (`net/protocol.ts`: join, room, laps, results, pings).
- **Inputs**: each step's input is quantized (steer -1000..1000, throttle and brake 0..1000, drift 0/1) and tagged with its step; a packet carries every input the server hasn't acknowledged yet (the last 12 steps at most), the first whole (5 bytes) and each next as what changed (a byte, plus a varint per changed value: a held key costs a byte a step), and the hashes of the client's predicted states at the snapshot steps it hasn't reported yet. The client drives its own car on exactly the quantized numbers the server will use.
- **Clock**: the client runs its own step counter a little ahead of the server's, so its input for step k arrives before the server simulates k. Each snapshot says how early the newest input arrived; the client's clock steers the low end of that over the last 4 s (its 5th percentile: one stall on the way - a packet TCP re-sends - is a blip to ride out, not a lag to jump to) to 2 steps - the server's **jitter buffer** - plus a margin it learns: a step more each time an input still arrives late, up to 8 (67 ms), a step less after a calm 10 s. It steers by running up to 6% fast or 5% slow; racing, it jumps only when more than 12 steps late (the lag went up for good) and never holds your car still to wait (before, a stall's late inputs made it jump ahead and then hold the car for up to a few hundred ms once the burst arrived - your own car froze or leapt). Not racing yet, it just moves. Snapshots that arrive in a burst cost one rewind (the newest; one carrying your corrected state is done first), not one each. An input that still arrives late is dropped and the server repeats the player's last one (counted as `late`). The server's own clock is hrtime: each step has its moment, the timer is set for the next one, a late wake runs the steps owed (never drifting), half a second behind drops the backlog.
- **Snapshots**, 60 Hz (every 2 steps), binary, one per client: every other car's **net state** (`arcade.ts` `netState()`: 72 numbers - where it is on the track, heading, slip, speed, yaw, the knock a hit left, the input its player is on (the newest the server has), the surface under it, its drift, boost tank and timers, its flight in the air, its laps and finish), each quantized to its own unit (`NET_SCALE`: 1/4096 u along the track, 1/16384 rad, 1/256 u/s ...) and sent as the change since the last snapshot - the WebSocket is TCP, so the last one is always there: only the changed fields, grouped by eight with a bit per changed group and per changed field, zig-zag varints. A cruising car costs ~15-25 bytes, a parked one 3; every client has had the same last snapshot, so a car's change is encoded once and the same bytes go to all (a client new to a car gets it whole). Then your race when it changes (laps, lap start, finish), the ack and how early your inputs arrive, whether your predicted state was right - and when it wasn't, your car's exact state: the 77 numbers of its simulation (`CORE_LENGTH`; the state's outputs follow from them exactly: `restoreCore()`), as the XOR change from the last one sent (unchanged numbers cost a bit, a number that moved a little ~6 bytes), at most 20 times a second (a client in a pack, wrong all the time, is told it was wrong in between).
- **Prediction - every car, in your own timeline** (`net/world.ts`, run by `net/client.ts`): your car moves the moment you press; every other car is simulated forward from its last snapshot on the input its player is on - the sim is deterministic, so that's exact until they change input - with car-to-car contact predicted against them, in the server's order (the grid slots). A crash happens on your screen the moment you make it, against cars drawn where they are now: nobody is drawn in the past, so a car beside you is beside you. A prediction that would put another car back on the track (a miss the server may not have seen) waits for the server instead: respawns are the server's to say.
- **Reconciliation**: each snapshot rewinds the whole world to the server's tick - your car to its exact state there (the server's, when your prediction missed; else the state you predicted and it confirmed), the others to the snapshot's - and replays to now. Each car keeps what's on screen where it was: the difference goes into its visual error, which decays (yours with a 60 ms time constant, ~95% gone in 180 ms; the others' 80 ms); a correction over 6 u (a respawn) snaps. A crash only the replay found plays late (its sparks and sound), unless one just played.
- **Car-to-car contact** (`net/contact.ts`, after every step, on the server and in the page): pairs close along the track (12 u) and in the world, in the same lane, neither a ghost; the two boxes are tested in the plane their up vectors share (separating axes on their 4 in-plane axes, plus their overlap along the plane's normal: a car in the air passes over one below unless they really meet). The contact normal is the axis they came together on - swept: the axis they overlapped on last, from where they were a step ago, so a 120 u/s car can't pass through another - or the least overlap for two that were already touching; the contact point is the incident face clipped against the reference face (a corner hit is at the corner; two flanks side by side touch in the middle of their overlap). The impulse: closing speed bounced back by 0.1 (none under 3 u/s or for a glancing scrape under 15 deg, fading in over 10 deg, as the walls), Coulomb friction 0.25, effective mass with both cars' yaw inertia (2.5 x a box's) about the contact, a step's yaw at most 1.5 rad/s a car; a car pressed against a rail takes no push into it - the rail holds that part (fully with its corner on it, fading out over 0.3 u off it: smooth, so a prediction a hair off doesn't push it another way), the other car takes the rest. Overlap is eased apart gently, as a position change only (25% a pass, at most 0.06 u, the heavier car moving less, never into a rail), 3 passes a step so a pack of ten settles without jitter. The step's sum goes to each car's `carHit()`: the stun / spin-out rules and the events the effects read. With one car in the room none of it runs; offline nothing of it loads.
- **Race flow** (`server/room.ts`): a room by name (the lobby browser lists them: `GET /rooms`); players join as their wallet (the session token) with a car and take the lowest free grid slot (the Sky Tower's own 8-car grid; on the meadow rows of two, 7 u apart, behind the line; more rows behind for more cars; up to 10); when everyone in the lobby is Ready there's a 3 s countdown and every car starts on the same step (and everyone is un-readied: Ready from the results on asks for the next race). A player can change car (`car`) any time: in the lobby the server swaps the car on its grid slot at once (the player is un-readied, so no countdown starts under the swap), during a race it waits for the lobby. Laps count by single player's rule, the finish order is by finish step, results are broadcast when everyone is in (or 30 s after the winner: the rest DNF). A car that has finished passes through the others. Respawns and wrong way are the driving model's own, as offline. A player who joins mid-race waits for the next one; one who leaves mid-race drops out.
- **Plausibility checks** (from day one; each counted per player, shown in the lobby, logged): a malformed packet is dropped (`format`); a value out of range is clamped (`range`); the steering may not move faster than the game's own key/pad smoothing allows - 12/s, 100 quantized units per step - against the previous step (`slew`, clamped); an input more than 2 s ahead of the server is dropped (`future`); more new steps than real time allows (126/s, bursts of 60) are dropped (`rate`). `&raw=1` makes a client skip the slew, to see them counted.
- **Race logs**: every race's applied inputs (only where they change), laps, leaves and its end (results, the race's contact counts, violations, a hash of every car's full state) go to `server/logs/<room>/<time>-race<n>.jsonl` (git-ignored; log version 3: the tamer car-to-car contact of `net/contact.ts` - older logs re-simulate only on their own code, `replay.ts` skips them; a bot's inputs are logged like a player's, so a replay doesn't run the bots). `npm run replay -- server/logs/<room>/<file>.jsonl` (`server/replay.ts`) re-simulates a race - every collision included - and checks the results, the contact counts and the state hash against the live race's. `node server/bench.ts <cars> <course> [laps] [race|spread|pack]` times the server's whole step (sim, contact, laps, log and every player's snapshot) with the players on the autopilot: a race from the grid, the cars spread round the lap (no one near anyone), or the worst case - every car aiming for the same spot all the time, a pack shoving constantly.
- **Stats**: `GET http://localhost:8790/stats` (locked with `STATS_KEY`; off in production without it) - the step time and how late each step ran (histograms), GC pauses, per room the step split (sim, sockets), contact counts, and per player bytes in and out, snapshots and full states sent; `POST /reset-stats` zeroes them. `GET /health` (200), `GET /version` (the sim build id). The page's `window.__online.stats` has its side (corrections, rollbacks, bandwidth).

Crash scenarios: a door-to-door nudge at 2 / 3.5 / 5 u/s closing moves the other car 0.24 / 0.42 / 0.73 u (its heading held; 0.3-1.0 u in half a second with the wheel left straight), 1-3 deg of wobble, no stun or spin; a T-bone at 20 u/s slides a car 2.6 u (was 4.2) and turns it 25 deg on its rear quarter (was 115 and a spin-out); at 40 and 50 u/s on the rear quarter it spins; a PIT by a heavier car spins a lighter one at 30-48 u/s; a car against the rail, pushed door to door or on its rear quarter: no wall hit, nothing off the rail (was a spin-out, a 29 u/s wall hit and 33 u/s off the rail); 120 u/s into a stopped car: no tunnelling, momentum kept within 1.3%. - **Races**: full 3-lap races of 4 clients on both courses, 1-lap races of 2 clients, of 4 at lag 150 / jitter 30, and of 2 clients with 4 server bots on both courses: everyone finished, every client got the same results, no page errors; every race's log re-simulates to the same results, contact counts and state hash. The single-player page is bit-identical: 12 cars x 3 laps on the autopilot give the same lap totals and trajectory hashes as before on both courses, and the page's own 3-lap race the same laps, events and final position. This round: 1-lap races of 2 clients with 6 bots on both courses and on the Sky Tower at lag 150 / jitter 30 (every client the same results, no page errors, every log re-simulating exactly); the corrections at lag 150 are as before - your car's only near another car (alone the prediction is exact), p95 0.002-0.013 u, at most 0.3-1.3 u (once ~3 u, in a pack); the other cars' p95 0.04-0.05 u, p99 0.4-0.8 (the bots ease off the throttle smoothly rather than flicking it, so they're predicted as well as players); single player still bit-identical (the same lap totals and hashes, the page's own race the same).

**Known limits**: no matchmaking; any signed-in wallet can join any open room (no NFT gating yet: `mayDrive`). A session token lasts its 24 h - *Disconnect* forgets it in the browser, the server can't revoke one early (short of a new `AUTH_SECRET`, which ends every session). Another player's car is predicted on the input it was last on, so when they turn or brake you see it a round trip later, smoothed (at 150 ms that's up to ~1 u, p99 0.5); a crash you predicted against a car that turned away may not have happened (its sparks played; the cars are put right). Browser and Node can differ in the last bit of `Math.exp` (same V8, other builds), so the prediction isn't bit-exact for long; the state hash is taken at a millionth of a unit, and the server is the reference for any re-simulation. The other cars have no engine sound or effects of their own beyond their crashes (sparks, flames). A hidden tab stops sending inputs (the server repeats the last one) and resyncs when shown. Car-to-car contact is boxes: a nose or a wing is as square as the rest of the car. A bot is predicted like a player's car, on the input it was last on (it's the server's to drive); a player who drives blind into the pack still crashes - the bots give way only to a car that has the place.

**Next steps**: WebTransport (unreliable datagrams) or WebRTC data channels instead of TCP (the deltas would then go against the last acknowledged snapshot); hosting the rooms on Cloudflare Durable Objects (a room per object, close to the players) or a small Node/Bun box per region; ranked races verified by re-simulating the stored input log on the server (`replay.ts` already does it); bot-detection statistics from the logs (input entropy, reaction times, steering spectra, how close a lap runs to the autopilot's); damage you can see (dents, a loose bumper) from the hits' severity; the bots predicted exactly - their autopilot run in the page too (it's deterministic; its few numbers of state would travel in the snapshot); a staggered grid on the Sky Tower (each car of a row a little behind the one inside it) if players crowd the plunge's funnel - the bots zip into it as it is.

## Review pages (dev server)

Dev mode's tools (the top bar links them in dev mode; they open by URL anyway):

- `/inspect.html`: every car in one place: list on the left, then a 3D viewer (clay, wireframe, preset angles), the sheet comparison, the reveal and the build report with its checks and manual retouch notes. The list comes from `asset-generation/assets/cars/index.json`, which every `ripcars` run rewrites.
- `/views.html?car=<id>[&m=<snapshot>]`: each ChatGPT sheet view next to the model, rendered from the exact same angle (raw texture, or tick *lit*). Use it to check shape, texture alignment and windows against the reference. `m` shows a snapshot instead of `model.glb`.
- `/compare.html?car=<id>&m=<a>,<b>,…`: versions of a model side by side, orbiting together. A name is a snapshot in `asset-generation/assets/cars/<id>/snapshots/<name>.glb` or `.fbx` (Tripo's raw FBX is normalised on load). `current` is the app's `model.glb`, and `scripted` is the scripts' model kept by `ripcars promote`. More options:

  | Option | Does |
  | --- | --- |
  | `refs=1` | adds the reference images |
  | `view=az,el,dist[,tx,ty,tz]` | starting camera: radians and model units. `az` 0 = right side, π/2 = front. Example: `0,1.5,7` is from above |
  | `glass=0` | opaque windows, showing exactly what is painted on the glass |
  | `clay=1` | untextured |
  | `fov=2` | near-orthographic |
  | `nogrid=1` | no ground grid |
  | `flip=<name>` | turns one model 180° |

## The live site (racecars.fun on Vercel)

- **`static/`** is the site's root: `favicon.svg` (the R mark) with `favicon-16/32.png`, `apple-touch-icon.png` (180), `icon-192/512.png` and a maskable 512 for `site.webmanifest`, `robots.txt` (the dev pages disallowed), `sitemap.xml` (the landing, `/online`, `/drive`) and `og.jpg` (the link preview, 1200 x 630). The dev server serves it at `/`; the build copies it into `dist/` (`vite.config.ts`'s `site-root` plugin). `node scripts/render-site.mjs` (the dev server running) redraws the PNGs from `favicon.svg` and `og.jpg` from the featured car's render and the wordmark.
- **Every page** has its title, the icons, the manifest and the theme colour; the public ones (landing, online, drive) a description and Open Graph / Twitter tags with `og.jpg`; the landing a canonical. The dev pages (rip, inspect, compare, views, stills) are `noindex`. `404.html` is the not-found page (Vercel serves it).
- **`vercel.json`**: clean URLs (`/online.html` → `/online`, query kept), HSTS, `nosniff`, a referrer policy, a permissions policy (no camera, mic, location, payment, USB, serial, Bluetooth, topics), `X-Frame-Options: SAMEORIGIN` with `frame-ancestors 'self'` (the inspector frames the reveal); hashed `/assets/*` cached for a year (immutable), the car files for a day (stale-while-revalidate a week: they aren't hashed), the pages `no-cache`. No script CSP yet: it would need testing against the wallets, images.ripcars.io, Google Fonts and the game server.
- **The game server** on its own host, `VITE_GAME_SERVER=wss://...` at build time; without it the online parts say offline (above). Hosting it on Fly.io: [server/DEPLOY.md](server/DEPLOY.md) (`Dockerfile`, `.dockerignore` and `fly.toml` at the repo root).
- **The sim build id** (`server/build-id.ts`): the page and the server deploy separately, and prediction needs the same sim on both, so both hash the shared sim code - the files under `src/` that `vehicles/arcade.ts`, `tracks/index.ts`, `input.ts` and `net/{contact,protocol,codec,race}.ts` import, and every car's `model.json` / `meta.json` - a plain content hash (a comment change is a new id). The build bakes it in (`vite.config.ts`'s `virtual:build-id`; the dev server recomputes it when one of those files changes), the server computes it at start; a join with another is refused and the page says *A new version is out* with a Reload button (the lobby and the landing say it from `GET /rooms`'s `version`, before joining). So deploy both when the sim changes. `node server/build-id.ts --files` prints the id and its files.
- **Restarts**: SIGTERM (a deploy) - no new joins or races, every player told (*Server restarts after this race*), and the server exits once no race is on, or after `DRAIN_S`; a second SIGTERM or Ctrl+C exits now.
